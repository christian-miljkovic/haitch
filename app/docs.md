# Noridoc: app

Path: @/app

### Overview

Next.js App Router routes for the storefront: the hero landing page, shop grid, product detail pages, editorial collections gallery, appointment booking, about, contact, and the custom checkout stepper. Pages are thin — they read data from @/lib and compose components from @/components, with styling in colocated CSS Modules plus @/app/globals.css.

### How it fits into the larger codebase

@/app/layout.tsx is the composition root: it wraps every page in `CartProvider` (from @/components/CartContext.tsx) and mounts the global `Nav`, `Footer`, and `BagDrawer`, so cart state is available on every route. Catalog-driven pages (`/shop`, `/products/[handle]`) call the synchronous `getProducts`/`getProduct` from @/lib/catalog.ts; image-driven pages read from @/lib/gallery.ts — `/` takes the local `HERO_IMAGE`/`HERO_IMAGE_MOBILE` `Photo` objects (`{ src, width, height }` pointing at @/public/home), while `/collections` takes `GALLERY_STACKS` — the local lookbook manifest (`{ src, width, height, group }` per frame, generated by @/scripts/import-lookbook.mjs) folded by `stackImages` in @/lib/gallery-layout.ts so consecutive near-identical frames become one tile — and hands the balanced columns to the client component @/components/GalleryGrid.tsx, which renders each tile as a @/components/GalleryStack.tsx and opens @/components/GalleryViewer.tsx full screen. `/checkout` renders @/components/CheckoutFlow.tsx, which ends by linking out to Shopify's hosted checkout.

### Core Implementation

|---|---|---|
| `/` | Static | Full-bleed hero `<picture>`: `getImageProps` is called twice with the same alt/`priority`/`sizes: '100vw'` and each `Photo` spread in (`{ ...common, ...HERO_IMAGE }`), the mobile call contributing only its `srcSet` to a `(max-width: 767px)` `<source>` and the desktop call supplying the `<img>` props; no custom loader. SHOP THE COLLECTION link |
| `/shop` | Static | Renders `ProductGrid` over `getProducts()` in line-sheet order (jackets, trousers, shirts) (4-across, hover image swap) |
| `/products/[handle]` | SSG via sync `generateStaticParams` | `notFound()` on unknown handle; `ProductGallery` scroll column + sticky purchase panel |
| `/collections` | Static shell | A one-line server component: `<GalleryGrid columns={balanceColumns(GALLERY_STACKS, 3)} />` (`balanceColumns` from @/lib/gallery-layout.ts). The client `GalleryGrid` renders each stack as a `GalleryStack` tile (one visible frame; tapping a multi-frame tile cycles it, tapping a lone frame opens it full screen) and owns the `GalleryViewer` dialog. Tile wrappers carry `--ratio`/`--scale` CSS vars and `order`; the first three tiles load their first frame eagerly |
| `/appointment` | Static shell | Renders client `AppointmentForm` (Formspree) |
| `/about`, `/contact` | Static | Brand copy / contact info |
| `/checkout` | Static shell | Renders client `CheckoutFlow`; all state is client-side |

The product panel in @/app/products/[handle]/page.tsx is driven by what the catalog entry carries: the price line renders only when `product.price` is defined, `AddToCart` renders only when `product.variants.length > 0`, a `SIZES: …` line shows the display-only size run, `SizeGuide` follows, then the description, and a MORE DETAILS section (`h2`) renders each `ProductDetailGroup` as an `h3` plus `<ul>`. Every committed look now carries a line-sheet `price`, so the panel today shows title, price, sizes, size guide, description, details, and the appointment/service links; `AddToCart` stays hidden because no look has variants yet.

Metadata uses the root template `%s — HAITCH`; each page exports its own `title`. `params` on the product page is a Promise (Next 16 convention) and is awaited.

### Things to Know

- There is no ISR anywhere on catalog routes: the catalog is in-repo, so `export const revalidate` was removed and both pages build fully static. Adding a look means editing @/lib/catalog.ts (and re-running the import script for photos), then redeploying.
- `/checkout` and `/appointment` pages are server components that only host client components — no data fetching happens on these routes.
- The old "MADE TO ORDER" note derived from a description regex is gone; the new line-sheet descriptions already end with "Made to order. 5-6 week production time."
- Every route image is a site-relative path served through Next's default image optimizer: look images (`/looks/look-N/NN.jpg`), lookbook frames (`/lookbook/NNNN.jpg`), and the hero (`/home/hero-desktop.jpg`, `/home/hero-mobile.jpg`). No page passes a `loader`, and no route relies on the `remotePatterns` allowlist in @/next.config.ts. `sizes` props are tuned per layout (e.g. `100vw` hero, `25vw` grid tiles, `55vw` gallery slides, `33vw` collections columns).
- The hero is two different photographs, not one image cropped twice: desktop gets a landscape colour frame and phones get a portrait black-and-white frame, so the `<picture>` swaps files at the 767px breakpoint. The intrinsic `width`/`height` that `getImageProps` uses come from the `Photo` constants in @/lib/gallery.ts and must match the committed JPEGs in @/public/home, which are hand-generated (no import script). @/tests/hero.test.tsx checks both files exist, that desktop is landscape and mobile is portrait, and that each `<source>`/`<img>` points at the right file.
- `/collections` balances *stacks*, not frames: each stack takes the size of its first frame, goes into the currently shortest of three columns, and every tile in a taller column is shrunk by that column's factor through `aspect-ratio: calc(var(--ratio) / var(--scale))` on the `.item` wrapper in @/components/GalleryGrid.module.css (a small `object-fit: cover` crop inside `GalleryStack`) so all three columns end on the same line with no ragged bottom. Real aspect ratios from the manifest make this computable at build time and let the page lay out at its final height before images load. On phones (≤767px) the columns collapse with `display: contents`, tiles re-sort into shoot order through the CSS `order` property, span the full width, and use the unscaled `aspect-ratio: var(--ratio)`. Re-running `npm run import:lookbook` regenerates the frames, the manifest, and therefore the grouping the page maps over.
- There is no CSS Module for `/collections` in this folder anymore: the grid rules (`.gallery`, `.column`, `.item`, the ≤767px collapse) moved to @/components/GalleryGrid.module.css, and gallery motion lives with the tile in @/components/GalleryStack.module.css. The tile *reveal* is no longer a CSS `view()` animation — @/components/GalleryStack.tsx flips a `revealed` state when an `IntersectionObserver` first sees the tile (fade + 32px rise over 0.9s, delay cascaded by `position % 3`), while the photo inside each tile still *drifts* on a CSS `view()` timeline where supported. Reduced-motion users get static tiles. Details in @/components/docs.md.
- The collections page stays a server component that computes the layout at build time; everything interactive — each tile's current frame and reveal state, the open-viewer `{ tile, frame }` state, and the full-screen `GalleryViewer` dialog — is client-side inside @/components/GalleryGrid.tsx and its children.
